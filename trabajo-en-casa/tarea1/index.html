Presentación

En esta actividad desarrollé un clasificador de modelos de servicios Cloud utilizando Python.

El programa analiza una descripción escrita por el usuario e identifica si corresponde a IaaS, PaaS, SaaS o FaaS.

El proyecto cuenta con interfaz gráfica, interfaz de línea de comandos y pruebas automáticas.

ARQUITECTURA

El proyecto fue dividido en diferentes archivos para separar correctamente las responsabilidades.

classifier.py

Contiene la lógica principal del clasificador, procesamiento de texto, reglas, puntuaciones y detección del modelo Cloud.

gui.py

Contiene la interfaz gráfica realizada con Tkinter y utiliza la función classify_text().

cli.py

Implementa una interfaz de línea de comandos utilizando argparse.

test_classifier.py

Contiene las pruebas automáticas del clasificador utilizando unittest.

✦

Objetivo

Mantener la lógica del clasificador independiente de las interfaces.

De esta forma la GUI y la CLI reutilizan exactamente la misma función de clasificación.

ERRORES ENCONTRADOS

01 · Dependencia de palabras clave

La primera versión dependía principalmente de palabras clave y expresiones regulares (Regex), por lo que las variaciones en mayúsculas, acentos o formas de las palabras podían afectar la detección.

02 · Entradas vacías

Fue necesario validar las entradas vacías para evitar intentar clasificar texto sin información suficiente.

03 · Evidencia insuficiente

Algunas descripciones pueden no contener evidencia suficiente para identificar IaaS, PaaS, SaaS o FaaS. Para estos casos se agregó el resultado “No clasificado”.

04 · Stemming básico

El stemming implementado es básico y está basado en reglas, por lo que puede producir coincidencias aproximadas y no tiene la precisión de herramientas de procesamiento de lenguaje natural más avanzadas.

05 · Conceptos relacionados

Algunos conceptos relacionados pueden aparecer simultáneamente, por ejemplo, “máquinas virtuales”, “máquina” y “virtual”. Esto no impide la clasificación, pero representa una limitación del sistema de conceptos.

Después de aplicar las correcciones, las seis pruebas automatizadas finalizaron con resultado OK y no quedaron errores críticos de ejecución.

05

MEJORAS REALIZADAS

01 · Separación de responsabilidades

Se separó la lógica del clasificador de la interfaz gráfica: classifier.py concentra la lógica y gui.py contiene únicamente la interfaz desarrollada con Tkinter.

02 · CLI independiente

Se creó una interfaz de línea de comandos con argparse. Tanto gui.py como cli.py reutilizan exactamente la función classify_text().

03 · Procesamiento de texto

Se incorporaron conversión a minúsculas, eliminación de acentos, limpieza de puntuación, normalización de espacios, tokenización, eliminación de stopwords, stemming básico y detección de conceptos relevantes.

04 · Reglas y puntuaciones

Se conservaron las reglas Regex y se combinaron con puntuaciones obtenidas a partir de los conceptos procesados.

05 · Validación de datos

Se agregó validación de datos y manejo de entradas vacías.

06 · Resultado sin evidencia

Se incorporó el resultado “No clasificado” cuando no existe evidencia suficiente.

07 · Pruebas automatizadas

Se añadieron pruebas con unittest para IaaS, PaaS, SaaS, FaaS, texto vacío y casos sin evidencia suficiente.

08 · CLI y validación de sintaxis

Se añadió la CLI y se comprobó mediante py_compile la sintaxis de classifier.py, gui.py, cli.py y test_classifier.py.

09 · Documentación

Se documentó el proyecto en README.md, incluyendo arquitectura, ejecución, procesamiento NLP, pruebas y limitaciones.
